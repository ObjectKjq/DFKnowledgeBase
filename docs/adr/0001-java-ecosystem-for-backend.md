# 后端采用全 Java 生态

RAG/检索领域的成熟开源实现几乎都在 Python（解析、embedding、rerank 模型生态），但我们决定后端整体采用 Java 生态，前端采用 TypeScript + React，由 Java 侧统一承担业务、检索编排与 MCP 服务端。原因：团队技术栈统一为 Java，长期维护与多人协作成本低于跨语言栈。代价是 OCR、文档解析、向量检索等能力需在 JVM 生态内选型或经标准接口调用外部/本地模型服务，具体组件与版本号待技术方案阶段确定。

**Considered Options**：
- Python 后端（RAG 生态最全）——因团队技能栈不匹配被否决，否则需要维护双语言栈。
- Java 业务后端 + Python 检索微服务——增加了部署与运维复杂度，与「单机 Docker 一条命令跑起来」的产品目标冲突，暂不采用。
