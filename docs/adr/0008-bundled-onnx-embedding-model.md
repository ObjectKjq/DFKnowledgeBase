# 向量模型固定内置 bge-small-zh-v15，对话模型走 OpenAI 兼容协议

中文知识库的语义检索需要中文向量模型。为实现零外部依赖（不强制部署 Ollama/vLLM 等模型服务），一期把 langchain4j 的 ONNX 嵌入模型 `bge-small-zh-v15`（512 维）打包进后端进程固定使用，不提供向量模型配置项（FR-7 的向量模型配置后置），ES 索引按 512 维建 mapping；对话模型（答案生成）按 OpenAI 兼容协议接入（服务地址 + 密钥 + 模型名），可指向任何兼容端点。

**Considered Options**：

- bge-m3（1024 维）经 Ollama/vLLM 自托管：向量质量更好、支持长文本，但引入外部服务与运维成本；被否决（一期），后续可作为可配置向量模型引入。
- 向量模型做成可配置端点（FR-7 完整体，切换需重建索引、维度可变）：配置面与重建复杂度高，一期收益低；后置。
- 内置 ONNX bge-small-zh-v15：被采纳。

**Consequences**：向量维度 512 写死在 ES mapping 与嵌入调用中；更换向量模型 = 全量重建索引（FR-11）；ONNX 推理在应用进程内，批量嵌入与入库线程池（ADR-0007）共享进程资源，是入库吞吐的限速点；对话模型的地址/密钥一期在配置文件中设置，实例设置界面（FR-7）后置。
