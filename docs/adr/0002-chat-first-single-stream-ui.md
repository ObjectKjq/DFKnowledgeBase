# 聊天为主的单消息流界面，不做独立搜索结果页

知识库产品的传统做法是「搜索框 + 结果页」，但我们决定界面以 Codex 式单消息流聊天为主体：检索结果卡片、引导澄清、带引用答案都呈现在会话流中，原文经右侧预览抽屉打开；文档管理、MCP 凭证、实例设置收敛到独立管理页。原因：目标用户处在「边问边核对」的连续场景，消息流天然保留每次检索的上下文与历史，且与引导检索、RAG 多轮追问等对话式行为形态一致；而撤销凭证、删除知识库等破坏性管理操作需要列表与二次确认，不适合聊天指令。

**Considered Options**：
- 传统搜索框 + 独立结果页：与引导检索、RAG 多轮追问的对话式行为割裂，被否决。
- 全部动作聊天指令化（含管理操作）：破坏性操作误触风险高、能力难发现，被否决。

**Consequences**：浏览式的内容发现体验较弱，主要依赖检索驱动；界面交互的权威定义集中在 PRD §6（界面与交互），实现阶段不得另起独立结果页。
