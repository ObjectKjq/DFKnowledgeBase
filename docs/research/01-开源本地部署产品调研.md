# 开源/可本地部署 AI 知识库产品调研

> 调研目的：为「可本地化部署的知识库平台」（支持关键字、图片、向量搜索与 RAG，提供网页客户端与 MCP 服务端，目标用户为学生与工作者）提供竞品参考。
> 调研时间：2026-10-16。信息以官方文档、官网、GitHub 为准；GitHub star 数与开源许可证变动频繁，请以各仓库页面为准（附链接）。

## 一、对比总表

| 产品 | 定位 | 关键词/向量/混合检索 | 图片搜索 | RAG 亮点 | MCP/智能体接入 | 部署 |
|---|---|---|---|---|---|---|
| Onyx（原 Danswer） | 自托管企业搜索 + AI 助手 | 混合检索（企业统一搜索） | 未见原生以图搜图 | Agents、Deep Research、40+ 连接器、查询时权限过滤 | **MCP 双向**：既做 MCP server 供 Claude/Cursor 等调用，也做 MCP client 承接工具 | 自托管，云端/本地模型皆可 |
| AnythingLLM | 一体化本地 RAG 工作台 | 向量检索为主，短文档整段进上下文 | 未见原生以图搜图 | 端侧 RAG（本地 embedding+向量库+reranker，带引用）、Workspace 隔离 | Desktop v1.8.0+ 支持加载 MCP 工具（作为 client） | Docker/桌面端/移动端，可全离线 |
| RAGFlow | 深度文档理解 RAG 引擎 | BM25+向量混合 + 多后端 rerank | 图片分块；VLM 解析 PDF/DOCX 内图片 | DeepDoc（OCR+版面+表格识别）、模板化分块、GraphRAG、知识图谱检索 | 提供 MCP server（访问数据集）+ OpenAI 兼容 API | Docker，可接本地/云端模型 |
| Dify | LLM 应用开发平台（含知识库） | 全文+向量+混合（权重或 Rerank 可调） | **多模态检索**（图片 embedding+多模态 rerank） | 多路召回、Rerank、跨文档引用、元数据过滤 | 支持 MCP（新版）；OpenAPI | Docker/私有化/云 |
| FastGPT | 企业级 Agent/知识库平台 | 向量 / 全文 / 混合（RRF 融合） | 未见原生以图搜图 | RRF 混合检索、Rerank 二次排序、可视化工作流 | 丰富 API 生态、HTTP 插件（OpenAPI 生成） | Docker/Helm，可接 Ollama 等 |
| MaxKB | 企业级智能体平台 | 自动分块+向量化，RAG 管道 | 未见原生以图搜图 | 文档上传/网页爬取、RAG 管道、工作流编排 | **MCP 工具调用** + 函数库 | Docker/1Panel 应用商店 |
| Khoj | 个人「第二大脑」 | 语义搜索（Transformer 模型）+增量搜索 | 未见 | 笔记/文档问答、联网检索、自动同步 | Emacs/Obsidian/桌面/网页客户端 | 可自托管于消费级硬件 |
| Quivr | 开源 RAG 框架「第二大脑」 | 语义检索（Opinionated RAG） | 未见 | 多 LLM、多文件类型、可插拔检索管道 | 可扩展管道（工具/网页搜索/自定义节点） | 自托管/云 |
| Verba | Weaviate 出品的模块化 RAG 应用 | 混合检索（BM25+向量） | 未见 | 模块化检索/生成组件，开箱即用 RAG | 未见 MCP | 依赖 Weaviate |
| Cherry Studio | 多模型聚合桌面客户端 | 知识库 RAG（内置向量检索） | 未见 | 文档/网页入库问答 | **完整支持 MCP server**（作为 client，可接数据库/文件系统等） | 桌面端，数据本地存储 |
| txtai | 嵌入式数据库 + 语义搜索框架 | 稀疏+稠密混合（BM25+向量） | 多模态 embedding（支持图像索引） | 图网络+关系库一体化、RAG/Agent 工作流 | 社区有基于 txtai 的 MCP 知识库 server | 库/自托管，可全本地 |
| Morphik | 多模态知识库检索 | 向量+视觉检索 | **以文搜图/多模态检索（ColPali 视觉向量）** | 视觉文档检索、图片 chunk 返回（base64/URL/文本） | API/SDK 为主 | 自托管/云 API |

> 图片搜索说明：绝大多数产品仅支持「图片内文字 OCR 后可搜」或「图片作为文档分块」，原生「以图搜图/以文搜图」在开源产品中很少见，是明显差异化空位（详见 02 号调研的多模态技术专项）。

## 二、各产品要点

### Onyx（原 Danswer）

- 自托管 AI 搜索与聊天平台，内置 Agents、Deep Research、40+ 数据连接器，任意云端或本地 LLM 均可运行（[Onyx 官网](https://onyx.app/)、[Onyx 文档](https://onyx-dot-app-onyx.mintlify.app/)）。
- **MCP 双向能力是同类中最完整的**：作为 MCP server，Claude Desktop、Claude Code、Cursor、Windsurf 等任何 MCP 客户端都可访问其知识库搜索/网页搜索/URL 抓取；支持 OAuth 授权接入，也保留 PAT/API key（[Onyx MCP Server](https://docs.onyx.app/deployment/configuration/mcp_server)、[Onyx Anywhere](https://docs.onyx.app/overview/onyx_anywhere/mcp_server)）；同时 Onyx 也能作为 MCP client 让其 Agent 调用外部工具（[MCP Actions](https://docs.onyx.app/admins/actions/mcp)）。
- 安全设计：文档与 embedding 留在自有基础设施、**查询时执行源权限过滤**（query-time permission enforcement）（[Onyx 官网](https://onyx.app/)）。
- 启示：「知识库 = MCP server」的产品形态已被 Onyx 验证，且 OAuth 接入体验值得借鉴。

### AnythingLLM

- 一体化交付：文档收集、embedding、向量库、聊天界面打包在一起，文件拖进 workspace 即可问答（[Agents-OSS 评测](https://agents-oss.com/projects/anything-llm/)、[官网](https://anythingllm.com/)）。
- 特色是**端侧 RAG**：移动端在设备内跑小 embedding 模型、本地向量库和 reranker，答案带引用且文档不出设备（[AnythingLLM Mobile](https://docs.useanything.com/mobile/overview)）。
- 短文档默认整段进上下文，超出上下文窗口才分块嵌入——「能不切就不切」的实用主义策略（[Agents-OSS 评测](https://agents-oss.com/projects/anything-llm/)）。
- MCP：Desktop v1.8.0 起可加载 MCP server 提供的工具（仅 Tools，不支持 Resources/Prompts/Sampling）（[MCP on Desktop](https://docs.anythingllm.com/mcp-compatibility/desktop)）；v1.9.x 持续重构 MCP 支持并新增 YouTube 抓取等能力（[v1.9.1 Changelog](https://docs.useanything.com/changelog/v1.9.1)）。
- 启示：面向学生/个人的「开箱即用 + 隐私」体验标杆；「短文档不分块」策略简单有效。

### RAGFlow

- 核心差异化是 **DeepDoc 深度文档理解**：OCR（含旋转校正）、版面识别（段落/表格/图片检测）、表格结构识别，为分块和检索提供结构化输入（[RAGFlow Glossary](https://ragflow.io/docs/glossary)）。
- 模板化分块：naive、版面感知、问答、表格、图片等多种分块模板，且分块结果可视化可审（[Tekai 评测](https://tekai.dev/catalog/ragflow)）。
- 检索：BM25+稠密向量混合，支持多 rerank 后端（默认 Elasticsearch，另有 Infinity、OpenSearch、OceanBase 等）（[Tekai 评测](https://tekai.dev/catalog/ragflow)）；GraphRAG 可作为分块方法，知识图谱（实体/关系/社区报告）可参与检索（[Notes and FAQs](https://ragflow.io/docs/dataset_notes_and_faqs)、[Release Notes](https://ragflow.io/docs/dev/release_notes)）。
- 智能体接入：官方 MCP server 可访问数据集；Agent 可经 OpenAI 兼容 API 调用；DeepDoc 支持用 VLM 做版面识别并深挖 PDF/DOCX 内图片（[Release Notes](https://ragflow.io/docs/dev/release_notes)）。
- 启示：文档解析深度直接决定 RAG 上限，「分块可视化」是很好的信任设计。

### Dify

- 检索模式：向量 / 全文 / 混合；混合检索可选「权重设置」（语义优先/关键词优先滑杆，无需 Rerank 模型）或启用 Rerank 模型（[索引与检索设置](https://dify-6c0370d8-release-1-16-0.mintlify.site/en/cloud/use-dify/knowledge/create-knowledge/setting-indexing-methods)）。
- **多模态检索已进入知识库**：图片可被 embedding、检索、多模态 rerank，作为 LLM 的视觉证据（[Dify 官方博客](https://dify.ai/blog/multimodal-retrieval-is-now-available-in-the-knowledge-base)）——是主流开源平台中图片检索走得最靠前的。
- 混合检索与 Rerank 的官方改进路线：多路召回 + 重排提升召回准确率（[Dify 官方博客](https://dify.ai/blog/hybrid-search-rerank-rag-improvement)）。
- 知识库可跨应用复用，元数据过滤支持租户/文档级隔离（[Hivebook 资料](https://hivebook.wiki/wiki/dify-open-source-llmops-platform-with-visual-workflow-builder)，二手来源）；2026 版本重点含 MCP 与 RAG v2、跨文档引用（[Dify 2026 综述](https://dify-hosting.com/en/blog/dify-whats-new-2026/)，二手来源）。
- 启示：检索权重滑杆是「让用户调 RAG」的低门槛交互；多模态 rerank 是图片搜索的可行路线。

### FastGPT

- 检索方案：向量检索 / 全文检索 / **混合检索（RRF 公式融合）**；混合检索范围大、无法直接按相似度过滤，官方建议配合 Rerank 模型重排并按 rerank 得分过滤（[知识库搜索方案](https://doc.fastgpt.cn/zh-CN/guide/dataset/dataset_engine)）。
- 面向企业交付：可视化工作流 + 丰富 API 生态，HTTP 插件可由 OpenAPI 快速生成，Rerank 兼容 Cohere 格式，支持 Helm 部署（[FastGPT 官网](https://fastgpt.io/)、[V4.7 更新](https://doc.fastgpt.io/en/docs/self-host/upgrading/outdated/47)）。
- 启示：RRF 混合 + rerank 已是中文开源社区的事实标准配方。

### MaxKB

- RAG 管道：文档直接上传 / 网页自动爬取，自动分块、向量化、RAG 问答（[MaxKB 官网](https://maxkb.pro/)、[文档](https://docs.maxkb.pro/)）。
- Agentic Workflow：工作流引擎 + 函数库 + **MCP 工具使用**，面向复杂业务编排（[1Panel 应用页](https://1panel.pro/apps/maxkb)）；国内私有化部署渠道顺畅（1Panel 一键安装）。
- 启示：「RAG 管道 + 工作流 + MCP 工具」三件套是国内企业级产品的标配组合。

### Khoj

- 定位个人「第二大脑」：用自然语言（Transformer 模型）搜索自己的 Org-mode、Markdown、PDF、纯文本、GitHub 仓库、Notion 页面；增量搜索、即输即搜（[Khoj 全功能](https://docs.khoj.dev/features/all-features/)、[概览](https://docs.khoj.dev/#/setup)）。
- 多端接入：Emacs、Obsidian、桌面端、网页端均可访问；可云可自托管，官方强调消费级硬件即可跑（[Self-Host](https://docs.khoj.dev/get-started/setup/)）。
- 启示：「文件夹/笔记工具自动同步 + 语义搜索」是学生场景的正确姿势；Obsidian/Emacs 插件入口值得借鉴。

### Quivr

- 开源 RAG 框架「第二大脑」，Opinionated RAG（预调优默认值开箱即用），支持 OpenAI/Anthropic/Mistral/Gemma/Ollama 等多后端（[Quivr GitHub](https://faraproject.com/QuivrHQ/quivr)、[Quivr 官网](https://www.quivr.com/)）。
- 文件支持 PDF/TXT/Markdown 及自定义解析器；管道可插拔（工具、网页搜索、自定义节点）（[x-cmd 资料页](https://www.x-cmd.com/install/quivr/)，二手来源）。
- 启示：「Opinionated（预调优、少配置）」与本项目「面向学生/工作者、不折腾」的目标高度一致。

### Verba

- Weaviate 官方的模块化 RAG 开源应用，检索采用**混合检索**（关键词 + 向量，兼顾精确匹配与语义匹配）（[Verba 官方博客](https://weaviate.io/blog/verba-open-source-rag-app)）。
- 依托 Weaviate 的混合检索与 rerank 能力（[Weaviate 检索概念](https://weaviate.io/developers/weaviate/concepts/search)）。
- 启示：产品本身较轻，主要价值在于示范「混合检索开箱即用」的产品化封装。

### Cherry Studio

- 多模型聚合桌面客户端：60+ 云端模型供应商 + Ollama/LM Studio/vLLM 本地模型；对话数据本地存储，支持 WebDAV 备份（[Cherry Studio 中文站](https://cherrystudiochina.com/index.html)、[英文官网](https://www.cherry-ai.com/)）。
- 内置知识库：导入 PDF、Word、Excel、TXT、Markdown 与网页，构建个人 RAG 助手（[英文官网](https://www.cherry-ai.com/)）。
- **完整支持 MCP server**（作为 client，可接数据库、文件系统、Web 服务等）（[英文官网 FAQ](https://www.cherry-ai.com/)）；跨 Windows/macOS/Linux（[Codersera 评测](https://codersera.com/blog/cherry-studio-complete-guide-2026/)，二手来源）。
- 启示：桌面端 + 本地数据 + MCP 的组合在个人用户中已有成熟心智，网页端 + MCP server 的组合反而少有人做。

### txtai

- 「嵌入式数据库」= 稀疏+稠密向量索引 + 图网络 + 关系数据库的合集，支撑语义搜索、RAG、Agent 工作流（[txtai GitHub](https://git-hub.com/neuml/txtai)、[PyPI](https://pypi.org/project/txtai-minimal/9.9.0/)）。
- 支持 BM25+向量的混合检索，多模态 embedding 可索引图像（[txtai 教程](https://www.rubythalib.ai/id/articles/tutorial-lengkap-txtai-database-embeddings-all-in-one-untuk-semantic-search-dan-llm-workflows)，二手来源；[txtai-xberg](https://pypi.org/project/txtai-xberg/1.3.6/) 含 OCR/PDF 提取扩展）。
- 社区已有基于 txtai 的 MCP 知识库 server（[kb-mcp-server](https://pypi.org/project/kb-mcp-server/)），证明「向量库 + MCP」的技术组合已被验证。
- 启示：技术栈选型参考——文本+图+关系三位一体的索引结构适合做统一知识库底层。

### Morphik

- 多模态知识库检索的代表：主打 **ColPali 式视觉文档检索**——不做传统版面解析，直接把文档页当图片做向量嵌入，检索时用 MaxSim 迟交互打分（[Morphik ColPali 文档](https://www.morphik.ai/docs/concepts/colpali)、[ColPali 概念](https://frutik.github.io/awesome-search/Concepts/ColPali)）。
- 检索 API 提供 `use_colpali` 开关，图片 chunk 可返回 base64/URL/Markdown 文本三种格式（[Retrieve Chunks](https://www.morphik.ai/docs/api-reference/retrieve-chunks)）；摄取与检索需成对使用 ColPali 模式（[Cookbook](https://www.morphik.ai/docs/cookbooks/generating-completions-with-retrieved-chunks)）。
- 启示：「以文搜图/以图搜文档」的视觉检索路线已有成熟 API 形态，是本项目图片搜索的直接参考。

## 三、共性与空位小结

1. **混合检索（BM25+向量）+ rerank 已是标配**（RAGFlow、Dify、FastGPT、Verba、txtai），RRF 是主流融合方式。
2. **MCP 正在成为标配接口**：Onyx 已做 MCP server + client 双向，RAGFlow/MaxKB/Cherry Studio/AnythingLLM 跟进；但「网页端知识库 + 对外 MCP server」的完整组合仍以 Onyx 为主要参照。
3. **图片搜索是最大空位**：主流产品只做到 OCR 文字可搜或图片分块；原生「以文搜图/以图搜图」只有 Dify（多模态检索）和 Morphik（ColPali）等少数玩家覆盖。
4. **文档解析深度决定 RAG 上限**：RAGFlow 的 DeepDoc、Dify 的多模态 rerank 是两个可借鉴的标杆。
5. **面向个人的体验设计**：AnythingLLM 的开箱即用、Khoj 的笔记同步、Quivr 的 Opinionated RAG、Cherry Studio 的本地数据优先，共同指向「不折腾、隐私、低配置」的个人产品定位，与本项目目标用户（学生/工作者）吻合。
