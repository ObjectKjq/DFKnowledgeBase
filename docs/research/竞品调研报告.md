# 本地化知识库平台 竞品调研报告

> 调研目的：为「可本地化部署的知识库平台」（支持关键字、图片、向量搜索与 RAG，提供网页客户端与 MCP 服务端，目标用户为学生与工作者）寻找参照产品、发现功能空位、输出功能扩展建议。
> 调研时间：2026-10-16。明细与完整来源见三份子报告：[01-开源本地部署产品调研](./01-开源本地部署产品调研.md)、[02-云端对照与多模态检索技术](./02-云端对照与多模态检索技术.md)、[03-自托管笔记知识管理工具调研](./03-自托管笔记知识管理工具调研.md)。

---

## 一、执行摘要

1. **赛道分三类**：开源 AI 知识库/RAG 平台（Onyx、RAGFlow、Dify、AnythingLLM 等）、自托管笔记/Wiki（SiYuan、Outline、Joplin、Obsidian 等）、云端 SaaS（NotebookLM、Glean、ima 等）。没有任何一家同时做好「本地化 + 三种搜索 + RAG + 网页端 + MCP server」的完整组合——**最接近的参照是 Onyx（MCP 双向）与 RAGFlow（检索深度），个人体验参照 AnythingLLM/Khoj/SiYuan**。
2. **两个最大空位**：① 图片搜索（以文搜图/以图搜图/图内文字三合一）在整个行业几乎空白，只有 Dify 多模态检索和 Morphik（ColPali）覆盖；② 「网页端知识库 + 对外 MCP server 供 Codex/Trae 等智能体调用」的组合，开源产品中只有 Onyx 完整做到。
3. **技术配方已收敛**：BM25 + 向量混合检索 → RRF 融合 → bge-reranker-v2-m3 精排 → 带引用生成，是 2025–2026 年的社区事实标准；文档解析（MinerU/Docling/PaddleOCR）深度决定 RAG 上限。
4. **MCP 已成智能体接入事实标准**（Outline、AFFiNE、Joplin、SiYuan、Onyx、RAGFlow 均内置），通行安全实践是 Streamable HTTP + token/OAuth + 默认只读 + 工具级开关；SiYuan 的 CVE-2026-66012 越权漏洞是前车之鉴。
5. **面向学生/工作者的产品共识**：开箱即用（Opinionated）、隐私本地、低摩擦采集（剪藏/文件夹同步）、答案引用到块/页级可跳转。

## 三、核心能力对比（要点级）

| 能力 | 行业现状 | 标杆 |
|---|---|---|
| 关键字检索 | 标配（FTS5/BM25/ES） | BookStack 高级搜索语法、Wiki.js 可插拔引擎 |
| 向量/混合检索 | BM25+向量混合 + RRF + rerank 已是开源标配 | RAGFlow、Dify、FastGPT、Weaviate/Verba |
| **图片搜索** | 行业普遍缺失；仅 OCR 图内文字可搜 | Dify（多模态 embedding+rerank）、Morphik（ColPali） |
| RAG 质量 | 分块可配置、rerank、引用溯源逐步普及；GraphRAG/Agentic RAG 属进阶 | RAGFlow（DeepDoc+分块可视化）、NotebookLM（逐句引用）、Glean（三路融合） |
| 多模态解析 | DeepDoc/Docling/MinerU/PaddleOCR 成熟可自托管 | RAGFlow DeepDoc、MinerU（中文/公式） |
| **MCP 接入** | 正在成为标配；server（对外供给）+ client（调工具）双向 | Onyx（双向+OAuth）、Outline（/mcp+Codex 示例）、Joplin（工具级开关） |
| 部署 | Docker/Compose 为主，本地小模型（Ollama/EmbeddingGemma/bge 系）支撑离线 | AnythingLLM 端侧 RAG、AppFlowy Vault 全本地 |

| 知识管理体验 | 树/标签/双链/剪藏/模板各有侧重 | SiYuan（块级+闪卡）、ima（微信剪藏）、Mem（自动整理） |

## 四、功能差距分析（本项目的空位机会）

1. **图片搜索三合一**：以文搜图（CLIP/SigLIP 多模态向量）+ 以图搜图（同向量场）+ 图内文字检索（OCR 入 BM25/向量）几乎没有竞品完整覆盖。技术路径明确：多模态向量 + OCR + caption 三路索引，RRF 融合（见 02 号报告 §第二部分-1）。
2. **「网页知识库 + MCP server」完整组合**：多数产品的 MCP 是「作为 client 调工具」或面向团队 Wiki；面向个人的、可被 Codex/Trae/Claude 等任意智能体连接的知识库 MCP server 只有 Onyx/Joplin 等少数实现，且均为文本检索工具。把「关键字/向量/图片检索 + RAG 问答 + 知识写入」全部暴露为 MCP 工具是明确差异点。
3. **面向学生/工作者的轻量定位**：开源 RAG 平台普遍偏企业/开发者（部署复杂、概念多）；笔记工具又缺 RAG/多模态。「不折腾、开箱即用、低配置可跑」的中间地带空缺。
4. **答案信任设计**：引用到块/页级并可跳转原文、分块可视化（RAGFlow）、答案投票反馈（Outline）在开源个人产品中普及率低。
5. **低摩擦采集**：浏览器剪藏、文件夹监听同步、微信/网页一键收藏（ima 验证了价值）在本地部署产品中薄弱。

## 六、风险与注意事项

1. **MCP 安全**：SiYuan CVE-2026-66012（匿名用户经 /mcp 调用文件读写工具）说明 MCP 端点必须做认证 + 角色校验 + 工具级权限，默认只读、凭证可过期可撤销（参照 AFFiNE 的 workspace 级凭证设计）。
2. **许可证**：自托管品类以 AGPL-3.0 为主（SiYuan/Joplin/Khoj/Logseq/AppFlowy），若闭源商用需避开 AGPL 传染；MIT（BookStack、txtai 系）与 Apache-2.0 系更宽松；Outline（BSL 1.1）、AFFiNE 后端（EE source-available）有商用限制。自研时建议核心自研 + 依赖宽松许可组件。
3. **资源占用**：多模态向量 + OCR + rerank 模型对内存/磁盘有要求，需设计「低配模式」（文本检索 + 远程 embedding）与「全功能模式」分档（参照 AnythingLLM 端侧思路、Surya/PaddleOCR-VL 均 <1B 可本地跑）。
4. **检索质量 vs 复杂度**：GraphRAG、ColPali 等建索引成本高，应做成可选索引而非默认路径。

## 七、结论

本项目的机会在于把三条已验证的线拧成一个面向个人（学生/工作者）的完整产品：**RAGFlow 级的检索深度（含图片三合一搜索）+ Onyx/Joplin 级的 MCP 供给能力 + AnythingLLM/SiYuan 级的开箱即用体验**。建议以 P0 清单为骨架立项，P1 形成差异化，P2 按需演进。
