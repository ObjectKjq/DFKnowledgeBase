## 问题陈述

用户已经能够登录平台、管理知识库、上传文本类文档、执行混合检索和带引用的 RAG 检索，但尚不能完成可靠的 P0 使用旅程：扫描 PDF 无法识别，检索模式与过滤不足，原文定位不完整，模型设置和 MCP 接入仍为演示。文件下载、关联与删除缺少业务内容权限检查，可能绕过知识库隔离；知识库恢复、文件字节回收和持久化排队也未形成完整闭环。

这些缺口使用户无法确信“文档全部入库、内容仅授权可见、答案可以核对、智能体调用真实有效”。本规格依据 2026-10-22 三轮评审结论，补齐现有平台的 P0；需求确认不表示实现或验收已经完成。

## 解决方案

交付以聊天单消息流为中心的完整本地知识库旅程：管理员创建用户并配置命名对话模型，用户上传普通文档或扫描 PDF，整份处理成功后通过混合、模糊、引导检索找到内容；用户可指定所选上下文进行 RAG 检索，打开原文核对引用，并通过三个只读 MCP 工具访问同一授权范围。

同步补齐内容权限、知识库与文档的 30 天回收站、手动及超期彻底删除、持久化入库排队、可恢复任务和真实管理页面。移除独立精确检索模式；联网搜索、图片搜索、独立图片文档入库及图片证据不在本次 P0。

## 实现决策

- **沿用现有架构**：后端保持 Java 单模块、业务分层、MySQL 持久化、Elasticsearch 自管索引及融合排序、Sa-Token 认证和平台 RBAC；平台角色与共享知识库成员角色保持独立。保留以聊天单消息流为主的 React 界面，以及独立管理页面。
- **规范与领域约束**：实现前加载对应前端或后端代码规范；使用现有术语、统一响应、分页与错误契约，更新前后端契约时保持一致。此次不重写已有且满足要求的基础能力。
- **身份与共享**：仅管理员创建用户并自动创建默认个人知识库；共享知识库仅所有者管理成员。默认个人知识库不可删；所有者不可退出或移除自己，不提供所有权转让。
- **文件存储与授权**：沿用文件元数据/内容分表的 MySQL 存储，以及先上传文件、再关联业务对象的两步流程。关联时校验文件可关联权限，读取按业务可见权限，删除按业务管理权限和引用关系；未关联文件由上传者管理。实例管理员无天然内容访问权，原文件接口不得成为授权旁路。
- **回收站与清理**：补充知识库删除状态、删除时间及恢复所需信息，支持原所有者 30 天内恢复并保留成员关系；文档沿用 30 天软删除。手动彻底删除再次确认，超期自动清理；只有不存在其他有效引用时才回收文件字节。保留历史答案，引用失效时显示不可用。
- **恢复状态**：原可用文档恢复先重建索引，完成后再可用；原处理中状态恢复后重新排队，原失败状态恢复为失败且可重试。知识库删除期间内容不得参与新访问，恢复也不能绕过文档就绪检查。
- **持久化调度**：继续使用 MySQL 状态机与线程池，不引入 MQ；默认同一知识库并发 1、全实例并发 2，管理员可调整。等待任务按提交顺序处理，忙碌知识库的等待任务不阻塞其他可执行知识库；队列满仍持久保存任务，禁止由上传请求代为解析，重启继续调度。
- **整份文档入库**：PDF、Word、PPT、Excel、TXT、Markdown，单文件上限 50 MB，暂不设单知识库容量上限，同名可重复。PDF 按页处理：文本页提取、无文本页 OCR。全部页面处理成功才统一索引，只有整份可用文档参与检索；任一页失败整份失败，返回页码和原因，重试保留首次失败原因。表格保留表头与行列对应关系。
- **OCR 实施边界**：扫描 PDF OCR 是 P0 产品要求，具体组件与部署方式未在本次讨论中选定；选型沿用 Java 生态及既有标准接口接入原则，若改变已定架构或增加需要用户配置的部署依赖，须明确说明影响，不能当作已经确认的产品决定。
- **检索契约**：仅四种模式。混合融合关键词和语义，模糊仅语义，引导最多两轮后混合，RAG 生成带引用答案；移除独立精确检索。检索增加文档类型、上传时间及范围过滤和分页，默认每页 20 条；输出高亮、定位、实际命中类型、相关性及当前有权范围内的索引中提示。标签过滤后置。
- **引导与会话**：支持推荐选项、自由输入及随时跳过；对话模型未配置或失败时解释原因并提供直接混合检索。持久化会话及每轮范围、过滤、模式、澄清和所选上下文，新会话重置默认模式，恢复会话恢复自身状态；改变选择只影响后续消息。
- **所选上下文**：RAG 请求支持所选分块；选择后仅使用这些分块，追问沿用、可调整或清空；未选择时自动检索。每次发送重新检查当前身份、知识库范围、分块权限与可用状态，不得把失权历史内容继续作为新答案依据。
- **引用与流式契约**：保留流式输出并标注正在生成，最终校验引用；依据不足或引用无效时完整替换暂定内容为拒答并清空暂定引用。只保留最终通过校验的答案或拒答结果，失败保留问题供重试；程序引用校验不替代真实样例的证据支撑质量验收。
- **预览契约**：PDF 原始页面及命中页；TXT/Markdown 原文及定位；Office 解析内容与适用的页码、幻灯片编号、工作表信息，不承诺完整排版还原。所有格式提供新页打开或原文件下载兜底；接口补齐必要的位置元数据，并在每次访问时检查权限和状态。
- **模型配置**：真实持久化多个命名对话模型配置，含名称、地址、密钥、模型名，按 OpenAI 兼容协议接入；连接测试返回真实结果、状态、时间和失败原因。聊天直接选择命名配置，不设独立档位；普通用户无配置权限，密钥不作为可重复读取的明文返回。
- **向量与重排**：继续内置 bge-small-zh-v15，固定 512 维，不新增文本向量模型切换和换维度流程。重排可选，未配置时保留融合排序；已配置模型不可用须明确报告，不静默切换其他模型。
- **MCP 模块**：实现真实 MCP 服务、凭证管理、工具分发、逐调用授权、调用记录和接入配置。三个工具为 `search`（混合/模糊）、`ask`、`list_knowledge_bases`，复用网页链路的业务检索与内容权限，禁止另造一套内容访问规则。
- **MCP 凭证**：绑定创建者，作用域恒等于用户当前有权内容，不独立扩大授权。独立工具开关、默认 90 天、可设 1～365 天、无永久凭证、创建仅展示一次令牌、支持即时撤销；过期、撤销、成员变化和总开关影响已建立连接中的新调用。默认每凭证每分钟最多 60 次工具调用，管理员可调整。
- **调用记录**：记录时间、工具、目标知识库、结果条数和来源凭证；失败与拒绝调用记录原因，日志不含文档正文或令牌明文。用户只看本人记录，管理员可看统计但不可看内容。
- **界面清理**：替换 MCP 与模型管理演示配置和假连接测试；补文档格式列、空知识库及索引中提示。首页入口为上传文档、向知识提问、连接 AI 智能体；不展示未交付的技能、图片查询或精确检索入口。
- **兼容与改动范围**：实施时显式处理现有文件归属、业务引用、知识库删除状态、会话模式及模型配置的存量数据迁移；不得简单删除现有数据或假定新部署。新增持久化结构和 API 的具体字段由实现阶段在现有契约内确定，不把本规格未讨论的表设计视为既定决策。

## 测试决策

- **已与用户确认的测试入口**：以后端 HTTP/MCP 边界的完整旅程为主，沿用现有前端组件测试验证交互；仅对 OCR、模型和外部服务使用可控替身，再以真实依赖验证一轮完整旅程。不为此引入横跨每层的新测试接口。
- **好测试的标准**：断言用户可观察结果、状态、权限及协议响应，不断言私有方法、内部调用顺序、组件内部状态或数据表实现。替身返回可控证据及故障，但不能把整个待验业务链路替换后声称闭环通过。
- **现有先例**：后端已有 JUnit、Mockito 服务测试和 MockMvc SSE 协议测试，覆盖检索、入库、知识库权限、文件服务、会话和 RAG；解析测试使用真实 PDF/Office 内容样本。前端已有 Vitest、Testing Library 和 jsdom 组件测试，按角色、文本及用户操作验证登录、用户管理和个人账号。优先复用这些装配，仅在现有服务层测试难以覆盖重启、数据库或协议行为时增加最高边界集成验证。
- **内容权限旅程**：至少两个用户与一个共享知识库，覆盖所有者/编辑者/查看者/非成员；直接文件编号访问、文件关联、下载、删除、预览、检索计数、RAG 与 MCP 均不能越权。建立 MCP 连接后移除成员，后续调用立即收紧；历史答案保留但引用不可再访问。
- **入库旅程**：上传各种支持格式、中文文本、同名文档、损坏文件、超限及不支持格式；文本/扫描混合 PDF、单页 OCR 失败、表格表头和行列关系；证实全页成功才可用，失败重试不产生可检索的部分内容。真实 OCR 验收不能仅依赖替身返回固定文字。
- **调度与恢复**：验证同知识库及全实例并发、多个知识库间排队、队列饱和、服务重启继续处理；上传请求不执行解析。采用可控同步点与状态观察，避免靠任意固定等待时间使并发测试侥幸通过。
- **删除清理旅程**：使用可控时间验证 30 天边界、手动彻底删除、超期清理及恢复索引；恢复知识库保留成员关系；有其他有效引用时不得清理字节，无有效引用时必须回收；新旧用户不能越过回收站权限。
- **检索与会话**：验证混合/模糊、组合过滤、每页 20 条及翻页、高亮、定位、相关性、OCR 来源、空结果与索引中提示。引导最多两轮、选项/自由输入、跳过、模型失败后的直接搜索；切会话恢复状态，新会话重置模式，历史消息不受后续选择变更影响。
- **RAG 与预览**：验证所选上下文不自动补搜、追问沿用和清空、所选内容删除/失权后的重新检查、无依据拒答、错误引用、权限撤回、跨文档结论、超时和重试。验证暂定流式答案在最终拒答时完整替换；检查 PDF 原始页、文本定位、Office 位置及原文件兜底。真实模型样例人工核对每项结论的证据支撑，不把引用编号合法等同答案正确。
- **模型管理**：管理员真实新增、保存、切换命名模型，验证连接成功/鉴权失败/超时及测试时间；普通用户不得修改，密钥不回显；可选重排未配置时仍可融合检索，模型故障有明确提示。
- **MCP 协议与管理**：真实客户端完成协议初始化、列出允许工具和工具调用；验证三个工具、工具开关、只读、令牌只展示一次、默认及自定义有效期、过期、撤销、限流、总开关、逐调用权限与审计隔离。拒绝或失败调用可追踪原因且不泄露敏感正文或令牌。
- **最终验收**：用真实数据库、索引、OCR、向量及对话模型完成“创建用户→共享知识库→上传整份文档→检索→所选上下文 RAG→原文预览→MCP→撤权→删除恢复→彻底清理”。记录依赖、数据、执行结果和不能验证的部分；测试存在、编译通过、页面存在或演示成功均不能替代该证据。

## 范围之外

- 独立精确检索模式及入口。
- 联网搜索、图片搜索（图内文字检索、以文搜图、以图搜图）、独立图片文档入库、图片 RAG 证据及相关技能入口；保留扫描 PDF OCR 文字入库。
- `search_images` 和任何 MCP 写入工具，包括 `add_note`；永久 MCP 凭证。
- 自助注册、共享知识库所有权转让、独立模型档位开关。
- 文本向量模型配置切换、维度切换和模型变更触发的完整重建索引功能。
- 标签管理及标签过滤、自动打标、重复检测、联网剪藏、完整离线/低配模式、深度检索、答案反馈、图谱、上下文化分块、页面视觉索引、音频及报告等 P1/P2 能力。
- Office 原始排版的完整还原。
- 移动端应用、企业 SSO/LDAP、多实例联邦检索，以及引入 MQ 或横向扩展架构。
