# P0 需求核对与讨论

日期：2026-10-22。状态：三轮结论已合并至 PRD v0.5；用户调用 to-spec 后，已发布为 [GitHub Issue #18](https://github.com/ObjectKjq/DFKnowledgeBase/issues/18)，标记 `ready-for-agent`。

## 当前 P0 范围摘要

- 保留混合、模糊、引导、RAG 四种模式；移除独立精确检索。
- 不做联网搜索、图片搜索、独立图片文档入库及图片证据；保留扫描 PDF 的 OCR 文字入库，整份处理成功后才统一索引。
- 用户由管理员创建；默认个人知识库不可删除；其余知识库和文档支持 30 天回收站、恢复与彻底删除。
- 修正文件关联、下载、删除的内容权限；彻底删除回收无有效引用的字节。
- 提供真实命名对话模型管理、可选重排、过滤分页、按格式预览及所选上下文。
- MCP 提供三个只读工具，落实凭证、工具开关、逐调用权限、过期撤销、限流、调用记录及总开关。
- 补齐持久化入库排队、并发限制和重启恢复；最终以完整旅程验证，不以演示界面或接口存在判定完成。

下文首轮核对是历史基线，后续已决结论优先；当前目标规则以 PRD v0.5 为准。

## 核对口径

依据《PRD-本地化知识库平台》v0.4 的 §6、FR-1～FR-7 及 §8，对照当前工作区代码、词汇表和 ADR。本文记录静态审查结果，不代表运行验收通过；本轮未执行测试。GitHub Issues 查询失败，未能核对远端需求讨论及关闭记录。

“已有实现”表示存在真实接口及调用链；“未完成”包含缺失能力和未接真实接口的演示页面。已被 ADR 后置的功能单列为范围冲突，不默认为实现遗漏。

## 关键证据

- `frontend/src/features/manage/McpTab.tsx`：明确标注凭证管理演示，不建立真实 MCP 接入。
- `frontend/src/features/manage/ModelsTab.tsx`：明确标注测试与保存为演示，未调用模型服务。
- `frontend/src/features/chat/Composer.tsx`：仅提供混合检索和 RAG 检索；没有图片查询、技能及模型选择。
- `frontend/src/stores/chat.ts`：模式保存在客户端状态；新会话未重置模式，切换会话未恢复各自模式。
- `src/main/java/com/df/knowledge/service/doc/DocParseServiceImpl.java`：无文本时明确返回“暂不支持扫描件 OCR”。
- `src/main/java/com/df/knowledge/service/doc/DocSearchServiceImpl.java`：固定执行文本向量与关键字混合检索，最多返回 20 条。
- `src/main/java/com/df/knowledge/controller/rag/vo/RagAskReqVO.java`：只接收会话、问题和范围，不接受选中的分块或图片证据。
- `frontend/src/features/chat/PreviewDrawer.tsx`：展示命中分块及页码等元数据，没有原始文档打开入口。

## 原 PRD 的其他验收缺口与边界

以下保留审查时的问题背景；最新结论以各轮已决记录及 PRD v0.5 为准。

- 共享知识库被邀请后，受邀用户侧未见事件推送或轮询，不能保证其侧边栏即时出现。`frontend/src/features/knowledge/useLibraries.ts` 目前依赖查询缓存刷新。
- 文档管理列表缺格式列；首屏缺“试试图片搜索”和“连接 AI 智能体”快捷入口。
- 当前实例设置演示页对所有登录用户可见；接真实配置时需同时落实管理员权限。
- 文档创建未校验待关联文件的归属，应与文件下载、删除一并修正。
- 入库线程池是全实例配置，未实现 PRD 的单知识库并发上限；队列满后调用方直接执行，不能保证统一按提交顺序排队。上限仍需定值。
- 超期清理删除了业务对象，但文件采用逻辑删除并保留数据库字节；“彻底删除”是否要求实际回收内容，需要明确并落实。
- 原先可用文档恢复后先重建索引，再进入可用，文档状态描述应同步此合理过程。
- 已删除与无权限引用目前统一提示不可用；如区分提示，必须避免泄露其他用户文档的存在性。
- RAG 已检查引用编号，但“每个论断都有证据支撑”仍需真实模型样例验收；流式展示在最终引用校验之前，需检查最终拒答时的展示行为。
- 表格目前按文字抽取，没有结构化表格对象；需要用跨行表头、合并单元格等样例确认 P0 所要求的“表格结构”保留程度。
- 仅独立图片三种检索属于 P0；caption、文档内嵌图片检索和页面视觉索引继续按 P1/P2 分期，扫描件 OCR 文本入库仍属于 P0。

实际 Elasticsearch 查询、ONNX 初始化、模型故障、逐句引用、多轮指代和并发删除恢复均未在本轮运行验证，不计作已验收。

## 内容隔离缺口

`FileController` 的下载和删除只按文件编号操作，`FileServiceImpl` 没有调用用户身份或知识库权限校验。已经登录的其他用户知道文件编号后，代码路径没有阻止其下载或删除文件。

这与 PRD §8.1 的内容隔离要求冲突，也与共享知识库移除成员后的访问收紧要求冲突。ADR-0009 明确规定删除不做引用/归属校验，因此修正时需要同步调整决策文档，不能只在检索接口补过滤。

建议作为 P0 优先修复项：文件关联业务对象后，读取按业务可见权限检查，删除按业务管理权限和引用关系处理；未关联业务对象的上传文件由上传者管理。具体共享文件及头像等用途的规则留待讨论。

## 首轮已决范围

用户确认：Q5 不纳入 P0，其余按推荐执行。

1. 完成真实 P0 闭环，包括模型管理界面，调整 ADR-0008 对设置界面的后置安排；保留内置文本向量模型。
2. 保留管理员创建用户的现有策略，将 PRD 自助注册描述同步为现有领域定义。
3. 默认个人知识库不可删除，其余个人知识库可删除；一期不做共享知识库所有权转让，所有者不能退出或移除自己。
4. MCP 仅交付只读能力，写入工具后置；落实工具开关、默认 90 天过期、撤销、审计及逐调用权限校验。工具数量已在 Q7 确认为三个。
5. 联网搜索和图片搜索不纳入本次 P0，包括三种图片搜索、相关技能和聊天入口；后续具体交付优先级另定。扫描件 OCR 与独立图片入库范围已在 Q8、Q16 明确。
6. 按 PRD 内容权限底线修正通用文件接口并更新 ADR-0009。

这些联动问题已在第二、第三轮讨论，下文包含待实施工作包与验收证据。

## 第二轮已决规则（Q7～Q13）

用户确认全部按推荐执行。

7. MCP P0 提供 `search`、`ask`、`list_knowledge_bases` 三个只读工具；`search_images` 随图片搜索后续交付。
8. 保留扫描 PDF 的 OCR 文字入库；独立照片、截图等图片文档入库随图片搜索后置。
9. PDF 预览原始页面并跳到命中页；TXT、Markdown 展示原文并定位；Word、PPT、Excel 展示解析内容，保留适用的页码、幻灯片编号或工作表信息。所有格式提供新页打开或下载原文件的入口；P0 不要求完整还原 Office 排版。
10. 管理员可配置多个命名对话模型，例如“快速”“标准”，用户直接选择，不再增加独立档位开关。文本向量模型内置；重排模型可选，未配置时使用现有融合排序。
11. P0 支持知识库、文档类型、上传时间过滤及分页；标签过滤随 P1 标签能力交付。
12. 提供手动彻底删除，超过 30 天自动清理；清除分块、索引及无其他有效引用的文件字节。历史答案保留，引用显示原文不可用；软删除仍可恢复。
13. 勾选结果后，RAG 仅使用所选分块；未勾选时自动检索。追问沿用所选内容，可清空；每次发送重新校验权限和文档状态。

上述规则替代首轮审查表中对应的旧范围描述，第三轮继续确定了入库、引用与清理规则。

## 第三轮已决规则（Q14～Q20）

用户确认：Q14 移除独立精确检索；Q16 全部处理后入库；其余按推荐执行。

14. 移除独立精确检索模式及入口；P0 提供混合、模糊、引导、RAG 四种模式。混合仍包含关键词匹配；模糊只使用语义匹配。MCP `search` 同步仅支持混合/模糊。
15. 引导检索依赖对话模型，最多澄清两轮，支持推荐选项、自由输入和随时跳过；模型未配置或失败时提示原因并提供直接混合检索。
16. 扫描 PDF 逐页处理，有文本的页直接提取，无文本的页执行 OCR。所有页面处理成功后才统一索引并标为可用；任一页失败则整份失败，显示页码与原因，允许重试。表格保留表头及行列关系，不要求还原视觉样式。
17. MCP 默认 90 天过期，可设置 1～365 天，不支持永久凭证；各凭证独立选择开放工具。默认每份凭证每分钟最多 60 次工具调用，管理员可调整；超限提供重试提示。失败与拒绝调用也记录原因，不记录文档正文或令牌明文。
18. 知识库软删除保留 30 天，仅原所有者可恢复，删除后成员立即无法访问；恢复时保留原成员关系。手动彻底删除需要再次确认，清理文档、索引及无其他引用的文件内容；默认个人知识库不可删除。
19. 保留流式 RAG，生成中标注“正在生成”；完成后校验引用，不足或无效时完整替换为拒答并清除暂定引用。失败保留问题供重试；验收增加无依据、错误引用、权限撤回、跨文档结论样例。
20. 同一知识库默认同时处理 1 份文档，全实例默认同时处理 2 份，管理员可调整；其余按提交顺序排队。队列满仍持久保存任务，上传请求不承担解析工作；服务重启后继续处理。
