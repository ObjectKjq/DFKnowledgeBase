# P0 真实依赖整合验收

## 验收环境与隔离

测试入口为 `P0RealDependencyJourneyTest`，通过 `-Dp0.acceptance.enabled=true` 显式启用。测试父 JVM 256 MB、Maven 384 MB，实际应用子 JVM 512 MB。子进程直接启动生产 `KnowledgeBaseApplication`，从 classpath 排除测试类目录，没有替换文件、权限、入库、索引、检索或 RAG 业务 Bean。

MySQL 使用本机 5.7.19，通过根进程 `P0_MYSQL_USER/P0_MYSQL_PASSWORD` 安全注入；测试不会把凭据写入命令行、文件或全局环境。ES 使用独立容器 `dfknowledge-p0-es-20261024` 的 127.0.0.1:19200（9.4.8 Basic + analysis-ik）。OCR 使用已验证的本地 Docker Tesseract 中文桥接器，向量使用实际内置 ONNX bge-small-zh-v15、512 维。

数据库和索引均为本次进程独有的 `df_p0_journey_{pid}_{序号}`；结束时强制终止本次创建的应用进程，清理这些隔离资源。不修改用户业务库或用户 es01/kib01，也不修改根进程保留的迁移预检库。

## 首个实际应用旅程

2026-10-24，`target/p0-real-journey-third.log`：1 项通过，0 失败、0 错误、0 跳过。实际旅程耗时 49.88 秒，Maven 总计约 64 秒。

验证顺序：

1. 真实管理员密码登录并创建所有者、查看者、编辑者及非成员，建立共享库和成员角色。
2. 真实上传 TXT、Markdown、混合文字/扫描 PDF、Word、PPT、Excel，确认文档仍在持久队列后强杀该实际后端 JVM。
3. 从同一隔离数据库启动新的后端 JVM，所有文档经过真实文件存储、解析、ONNX、ES Basic 和中文 OCR 后整份可用。
4. 长文档实际跨过 20 条默认分页，验证混合、模糊、格式过滤、计数、相关性、全文解析预览及原文件字节；实例管理员和非成员不能读取共享内容，查看者不能上传或恢复。
5. 混合 PDF 第二页具备真实中文 OCR 文本和页码；所选上下文通过显式本地模拟模型生成引用答案。
6. 文档软删除与索引恢复、知识库删除恢复并保留成员、移除成员后新检索/RAG/文件访问收紧；彻底删除后直接检查真实 MySQL 文件内容表确认字节已回收。

本地模拟模型仅验证流程、模型选择和引用协议，不作为真实生成能力或证据支撑质量通过的依据。

## 真实联调发现与修复

第二轮实际 `/api/system/auth/login` 返回 401，应用日志显示请求在进入认证服务前被登录拦截。此前 HTTP 装配均使用空 context-path，未覆盖默认 `/api` 部署；SaRouter 的排除路径没有剥离该前缀。

修复为全路径注解鉴权拦截器，加上通过 MVC `excludePathPatterns` 排除公开路径的单独登录检查；保留精确 `/mcp` 独立凭证认证，MCP 管理路径仍受网页登录约束。实际 `/api` 完整旅程随后全部通过。该问题属于产品缺陷，未通过改变测试 context-path 或绕过身份服务掩盖。

第一轮 ES 索引准备曾误把 HTTP 模板中的 `{{esUrl}}` 当作 JSON 起点；这是验收脚本错误，已改为独立 JSON 行定位，不计为产品失败。
