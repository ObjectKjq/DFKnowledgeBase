# 文件权限与删除实现

2026-10-28：已移除知识库和文档回收站，以下行为替代原回收站方案。

## 当前行为

- 上传记录 `uploader_id`；未关联文件只允许上传者读取、关联和删除。关联后按当前知识库内容权限判定，上传者与实例管理员没有额外内容访问权。
- 文档删除直接清理检索索引、分块和文档记录，不再保存删除时间或删除前状态，不提供恢复和二次彻底删除接口。
- 知识库仅所有者可删除，默认个人知识库不可删除。删除时同步清理文档、成员关系和知识库记录。
- 文件引用与字节回收共用文件行锁；存在其他文档引用时保留文件，最后一个引用移除后物理删除元数据与 `LONGBLOB`。
- 保留历史会话及答案，原文已删除的引用不可再访问。删除确认由页面提示不可恢复。
- 创建文档只保存排队状态，由 `DocParseJob` 每十分钟扫描待处理文档。删除和入库遵循知识库在前、文档在后的加锁顺序，防止已删除内容被旧任务重新写入索引。

## 数据库升级

新部署使用 `sql/schema.sql`。已有部署先升级到 SQL016，停止应用并备份，再执行一次 `sql/upgrade/017-remove-recycle-bin.sql`，最后启动新版应用。

SQL017 清理旧回收站对象和无其他引用的文件内容，再移除 `knowledge_base.delete_time`、`knowledge_doc.delete_time` 和 `knowledge_doc.prev_status`，避免删除字段后旧数据重新出现。历史磁盘文件不由 SQL 删除，应先保存脚本查询输出，核对路径后清理。历史 SQL 升级脚本保留以支持按顺序升级，不是运行时回收站代码。

## 验证

`ContentLifecycleHttpTest` 使用隔离库 `df_knowledge_base_p0_19_test`，显式传入 `-Dp0.mysql.enabled=true` 执行。覆盖未关联文件隐私、成员权限撤回、默认知识库保护、共享文件最后引用回收、知识库级联删除，以及 SQL017 清理旧数据并保留正常共享引用。

前端管理页面的测试验证删除确认后调用正常删除接口并更新列表；后端 OpenAPI 测试验证已移除回收站接口和字段，并导出 `target/openapi.json` 供前端 API 生成。
