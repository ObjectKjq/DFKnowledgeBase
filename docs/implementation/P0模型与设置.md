# P0 命名模型与实例设置

## 数据迁移与接口

已有部署先执行 `sql/upgrade/013-model-settings.sql`，新部署使用 `sql/schema.sql`。升级仅新增模型配置与实例设置，不删除旧内容。

启动时将旧 `knowledge.rag.base-url/api-key/model`（对应 `CHAT_MODEL_*` 环境变量）迁移为“旧配置迁移的对话模型”。迁移标记持久化于实例设置，管理员删除迁移项后不会在下次启动复活；修改配置后无需重启生成端口。

管理员通过 `/system/model/create`、`update`、`delete`、`get`、`list`、`test` 维护配置，必须具有 `instance_admin` 角色。普通登录用户仅通过 `/system/model/simple-list` 读取编号、名称及 `simulated` 标记。密钥不出现在读取响应中；更新时不传 `apiKey` 表示保留，传空字符串表示清除。修改配置会清空旧测试时间和原因，并回到 `UNTESTED`。

真实连接测试实际调用 `/chat/completions` 或 `/rerank`，保存 `SUCCESS/FAILED`、时间及安全原因。鉴权失败、超时和不可达分别返回中文原因，不保留提供方原始错误正文。测试成功只证明接入和响应格式可用，不代表答案质量通过验收。

`ModelConfigurationService#resolveChatModel` 按编号选择模型；省略编号时选择编号最小的当前可用对话配置。指定模型故障不静默切换。`RagGenerationPort.GenerationRequest` 携带 `modelId`，引导可调用 `ModelConfigurationService#chat`。向量模型仍固定为内置 bge-small-zh-v15、512 维。

可选重排使用 [Jina 官方 API](https://docs.jina.ai/) 所示的 `/rerank` JSON 兼容协议：请求 `model/query/documents/top_n`，响应 `results` 中每项包含 `index/relevance_score`，须覆盖全部候选。`ModelRerankService#rerank` 未配置时返回原融合顺序，配置后真实调用，故障显式报错；重排只改变候选顺序并保留原对象元数据。

`InstanceSettingsService#get` 每次从 MySQL 读取当前设置，供调度和 MCP 逐调用复用。默认 MCP 开启、每凭证每分钟 60 次、全局入库并发 2、单知识库并发 1。管理员接口为 `/system/settings/get` 和 `update`。

## 本地模拟模型

用户明确授权在没有真实模型时，先写死模拟响应验证完整流程。`application-local.yaml` 中 `knowledge.model.mock-enabled: true` 启动后创建“本地模拟模型（非真实生成）”。它使用仅内置项允许的 `mock://local` 地址；管理员创建真实模型仍必须填写无凭据与查询参数的 HTTP/HTTPS 地址，不能自行创建 mock 地址。

选择模拟项后，引导返回固定的主题澄清问题与三个选项；RAG 复述首个本轮有效证据并携带该证据编号，答案始终带“本地模拟，非真实模型生成”前缀。无证据时拒答。模拟连接测试状态为 `SIMULATED`，不标为真实 `SUCCESS`。它不能证明真实模型的生成、推理与引用支撑质量。

将 `knowledge.model.mock-enabled` 改为 `false` 并重启，即从用户选择列表排除模拟项，按旧编号请求模拟项也会拒绝执行；管理员仍可查看并删除已持久化的模拟项。真实模型故障不会切换到模拟模型。

## 验证范围

模型管理测试使用本机 MySQL 隔离数据库、真实 HTTP 端口和实际 Sa-Token/RBAC 查询；外部模型用本机可控 HTTP 服务覆盖成功、鉴权失败、超时、不可达与重排协议。测试数据库以 `df_p0_model_` 为前缀，在测试后删除，不改动业务数据库。

目前没有用户可用的真实模型服务。最终真实对话模型与证据支撑质量验收仍需后续提供真实命名模型配置；模拟响应与可控外部服务不计作该验收通过。

运行真实 MySQL 管理旅程：

```powershell
$env:JAVA_HOME='C:/Users/EDY/.jdks/ms-21.0.12'
mvn '-Dmaven.repo.local=D:/naven/repository' '-Dp0.mysql.enabled=true' '-Dtest=ModelConfigurationControllerTest' test
```

常规测试默认跳过需要本机 MySQL 的管理旅程。显式启用后，数据库连接或建库失败会使测试失败，不会降级为跳过。
